# ADR-0010: 本地分流规则设计

**状态：** 已接受
**创建时间：** 2026-07-14

> 当前状态 / 核心结论：`[filter_local]` 现为六层结构（版权保护 / 广告下沉 / 开屏 SDK / 金融直连 / 误收录放行 / IP 直连 + 兜底），共 143 条；规模较初版扩大，原因是承接了上游已停更源与零信誉新源中无法用远程规则表达的内容，以及上游误收录的修正规则。

## 背景

远程规则集覆盖了绝大多数服务的分流需求，但某些流量需要本地规则优先处理：金融类服务必须直连以确保稳定和安全，P2P/版权内容需要拦截，特定 IP 段需要绕过代理。此外上游广告源存在误收录与误杀，需要本地规则修正。

## 决策

在 `[filter_local]` 中定义五层本地规则，优先级高于未开启 `inserted-resource` 的远程规则：

| 类别 | 规则 | 策略 | 理由 |
|------|------|------|------|
| 版权保护 | `hub5*.v6.shub.sandai.net` | REJECT | 屏蔽迅雷 P2P 版权检测 |
| 广告下沉 | 72 条国内 App 广告域名（原有 7 条 + 新增 65 条，如 `ad.kugou.com`、`ad-cdn.cctv.com`、`ad.xueqiu.com`） | REJECT | 承接上游已停更源中无法远程表达的规则 |
| 开屏 SDK | 38 条主流广告 SDK 投放端点（穿山甲 `pangolinsdk.com`、快手 `adse.kuaishou.com`、阿里妈妈 `mmadx.taobao.com`、厂商广告 `ad.oppomobile.com` 等） | REJECT | 现有远程源对国内开屏广告 SDK 覆盖不足，且上游来源信誉不足不宜订阅 |
| 金融直连 | 18+ 家银行域名后缀（`icbc.com.cn`、`ccb.com` 等） | DIRECT | 金融交易必须直连，避免代理引入的安全风险和不稳定 |
| 误收录放行 | 被上游广告源误判的正常域名与安全服务（`www.95599.cn`、`safebrowsing.googleapis.com`、`safebrowsing.urlsec.qq.com`，共 5 条规则） | DIRECT | 修正上游误收录；拦截安全浏览 API 会削弱浏览器钓鱼防护 |
| IP 直连 | `188.180.0.0/16` | DIRECT | 该网段强制直连（运营商内网或无需代理的 CDN） |

兜底策略 `FINAL, 漏网之鱼` 使未匹配的流量进入 漏网之鱼 策略组。

**规模约束**：本地规则只承接两类内容——必须确定性优先的关键流量，以及远程源无法表达或表达错误的内容。远程源能覆盖的规则一律不写进本地。

**放行层的层级要求**：放行规则须覆盖上游实际使用的**全部类型层级**。实测上游对同一域名可能同时以 `HOST` 与 `HOST-SUFFIX` 两种类型收录（`safebrowsing.googleapis.com` 在 Privacy 与 Google 中是 `HOST`，在 Advertising 中是 `HOST-SUFFIX`），只放行一层会被另一层抢先命中而静默失效。

## 后果

- 金融类域名本地直连，避免代理节点故障导致银行/支付不可用，也规避数据经境外节点的合规风险。
- 迅雷域名 REJECT，阻止 BitTorrent 相关流量。
- 本地规则由约 20 条增至 143 条，维护成本上升；广告下沉层与开屏 SDK 层需随上游变化人工复核。
- 本地规则优先级高于未开启 `inserted-resource` 的远程规则，确保关键流量的确定性路由；已开启该参数的远程源其规则会前置到本地之前（当前仅 Hijacking，见 ADR-0015），因此放行层所在的 Advertising 与 Privacy 必须保持不前置，否则放行静默失效。
